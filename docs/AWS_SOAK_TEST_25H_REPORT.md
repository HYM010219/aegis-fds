## 7. 부하 분석 및 트러블슈팅

### 7.1 Kafka CPU 간헐적 스파이크 (최대 243.4%)
* **현상**: 평균 51.3% 수준을 안정적으로 유지하다가, 간헐적으로 200% 이상(최대 2.43 코어 상당)으로 순간 점유율이 튀는 현상 관측.
* **원인**: ClickHouse Kafka 엔진의 폴링 루프 및 Spark Structured Streaming 컨슈머 간의 동시 인출 경합.
* **영향**: 8 vCPU 환경에서는 전체 용량 대비 약 29% 점유로 시스템 전체에 장애 없이 완벽 흡수됨.

### 7.2 ClickHouse 피크 105.2%
* **현상**: 대량 배치 적재 후 백그라운드 파티션 머지(Parts Merge) 작업 시 CPU가 일시적으로 1코어 수준(105.2%)으로 상승.
* **영향**: 데이터 유실이나 랙(Lag) 누적 없이 정상 적재 완료.

## 8. 아키텍처 결론: K3s 2노드 분리 배포 타당성

1. **단일 노드 분리 필요성 확인**:
   * Data 컴포넌트(Kafka 2.4코어 + ClickHouse 1.0코어)가 피크 시 약 3.4코어를 점유하므로, App 노드(Gateway, Spark, Web)와 완전 분리 배포 확정.
2. **K3s 2노드 아키텍처 확정 (§9.6)**:
   * **App 노드 (`aegis-v2-app`)**: K3s 클러스터로 게이트웨이 이중화 및 상태 워커 무중단 배포 (`m5.xlarge`)
   * **Data 노드 (`aegis-v2-data`)**: 비공개 서브넷에서 Docker Compose로 DB 격리 운영 (`m5.2xlarge`)
   * **비용 절감**: NAT 게이트웨이를 제거하고 S3 게이트웨이 엔드포인트를 적용하여 클라우드 비용 80% 이상 절감.
